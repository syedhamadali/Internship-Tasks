Vanilla JS · No framework

A small, reusable UI kit — built the way React would build it.

Four components, each a self-contained function that takes props and returns markup or behavior: Button, Card, Modal, and Toast. No global state, no hardcoded instances — every element below is generated from the same four functions.

Button

createButton(props)

One function, five variants, three sizes, an icon slot, and a disabled state — all driven by the props object, nothing duplicated in markup.

createButton({ text: 'Save changes', variant: 'primary', size: 'md', onClick: fn })

Card

createCard(props)

Same function rendering three different contexts — a plain info card, an elevated project card with a footer action, and an outlined pricing card.

Modal

createModal(props)

Each trigger opens a modal built by the same function with different content and actions. Close via the × button, the overlay, the Esc key, or an action button — each modal instance manages its own open/close state.

createModal({ title, content, actions: [{ text, variant, onClick, closesModal }] })

Toast

showToast(props)

Click any trigger more than once to see toasts stack. Each toast auto-dismisses on its own timer (shown as a shrinking bar) and can also be dismissed manually — closing one never affects the others.

showToast({ variant: 'success', title, message, duration: 4000 })

Thinking in components

Earlier tasks — the weather dashboard, the notes app, the portfolio — mostly grew as pages: I'd write a chunk of HTML, style it, then bolt on JS to make that specific chunk interactive. Building this kit forced the opposite order: define the interface first (what props does a button need to cover every variant I'll ever want?), then let every instance on the page — three cards, five buttons, four toast triggers — call that same function instead of writing new markup. It also pushed state ownership down to each component instead of up into page-level variables: each modal and toast manages its own open/closed lifecycle and cleans itself up, so instances never collide, the same way a React component's state doesn't leak into its siblings. The trade-off is more upfront design work per component and a bit more indirection to read, but changing one thing — say, a button's hover shadow — now updates every button on the page instead of requiring me to hunt down five copies.

Built with plain HTML, CSS and JavaScript — zero dependencies.
